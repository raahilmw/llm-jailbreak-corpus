## 1. DNS Tunneling

### (a) Wire artifact
```
<base32-encoded-data>.<seq>.<domain>.tunnel.example.com A?
e.g. x7f9k2m1q4p8r3s5.0001.mytunnel.example.com TXT?
```
Label length >30 chars, entropy high, TXT queries dominate, single NS under attacker control answers.

### (b) Log source / field
- Zeek `dns.log`: `query`, `qtype`, `rcode`, `AA`
- Windows DNS Server analytical log: Event 3068, field `QName`
- Umbrella/Quad9: `domain_name`, `answer`

### (c) Rules

**Suricata** (long-label + TXT ratio):
```
alert dns $HOME_NET any -> any any (msg:"DNS tunneling - long label"; dns.query; pcre:"/(?:[a-z0-9]{30,}\.){2,}/i"; sid:1000001; rev:1;)
alert dns $HOME_NET any -> any any (msg:"DNS tunneling - TXT to single domain burst"; dns.query; content:".tunnel.example.com"; sid:1000002; rev:1;)
```

**Sigma** (client-side tooling):
```yaml
title: DNS Tunneling Tool Execution
status: experimental
logsource:
    product: windows
    category: process_creation
detection:
    selection_img:
        Image|endswith:
            - '\dnscat2.exe'
            - '\iodine.exe'
            - '\dnsexfil.exe'
    selection_cmd:
        CommandLine|contains:
            - 'dnscat2 --domain'
            - 'iodine -f'
    condition: selection_img or selection_cmd
level: critical
tags: [attack.exfiltration, attack.t1071.004]
```

**SPL** (statistical, catches unknown tools):
```spl
index=dns | stats count, avg(len(query)) as avg_len,
       max(len(query)) as max_len,
       dc(query) as uniq_q by query_suffix
| eval query_suffix=mvindex(split(query,"."),-2).".".mvindex(split(query,"."),-1)
| where count > 100 AND avg_len > 40 AND uniq_q/count > 0.9
```

### (d) FP analysis / tuning
- **DKIM/SPF selectors** (`s1024._domainkey.`) → exclude `*._domainkey.*`, `*._dmarc.*`
- **CDN long labels** → allowlist `*.cloudfront.net`, `*.akamaiedge.net`, `*.azureedge.net`
- **Software update hashes** (`*.windowsupdate.com`) → cap label length at 45 for allowlisted suffixes
- Tune the SPL threshold: `uniq_q/count > 0.9` is the key discriminator — tunneling never repeats a query; C2 beacons do.

### (e) Missed evasion
**Low-and-slow with spread across many NS domains.** Volume-based thresholds (`count > 100`) fail when the operator encodes 1 KB/day across 50 rotating domains. The per-query Suricata rule survives, but only if labels stay >30 chars — an operator using 20-char labels with 4-char chunking (AAAA queries, hex data that looks like IPv6 prep) defeats both. Reason: signature depends on label length and volume; neither is intrinsic to the channel.

## 2. HTTPS Domain Fronting

### (a) Wire artifact
```
TLS ClientHello: SNI = allowed.front.cdn.net
HTTP/1.1 Host: forbidden-destination.example.com
```
The mismatch itself is the signature. (True fronting is dead on AWS/GCP/Azure — they enforce SNI=Host — but detection must cover non-enforcing CDNs and the successor technique.)

### (b) Log source / field
- Proxy with TLS interception: `ssl_sni` vs `http_host` fields (Zscaler: `ssl_sni`/`url_host`; Bluecoat: `sni`/`cs-host`)
- Zeek: `ssl.log` `server_name` joined to `http.log` `host` on the 4-tuple
- WAF: `Host` header field

### (c) Rules

**SPL** (Zeek join):
```spl
index=zeek sourcetype=zeek:ssl
| join src_ip, dst_ip, dst_port [search index=zeek sourcetype=zeek:http
    | rename src_ip as src_ip, dst_ip as dst_ip, dst_port as dst_port
    | table src_ip dst_ip dst_port host]
| where server_name != host AND server_name != "NULL"
| stats count by src_ip, server_name, host
| where count > 3
```

**Suricata** (fronting to known-bad backend):
```
alert http $HOME_NET any -> any $HTTP_PORTS (http.host; content:"forbidden-destination.example.com"; sid:1000003; rev:1;)
```

### (d) FP analysis / tuning
- **Legit SNI/Host mismatch**: regional endpoints (`Host: api-eu.example.com`, SNI `example.com`), apex vs `www`, trailing-dot FQDNs → normalize both fields (strip trailing dot, lowercase, strip port) before compare; allowlist pairs where SNI is a suffix of Host or vice versa.
- **ESNI/ECH handshakes** produce `server_name = NULL` → exclude, but alert separately on ECH extension presence (see evasion).
- Threshold `count > 3` kills one-off client quirks (browsers retrying with bare IP SNI).

### (e) Missed evasion
**Encrypted Client Hello (ECH).** ECH encrypts the inner SNI; the outer SNI is a benign public-name cover domain. The proxy sees `SNI = cover.cloudflare-ech.com` and, without TLS interception, no HTTP layer at all — the mismatch field simply doesn't exist. Rule fails because it requires both values in cleartext. Also: **domain hiding** via CDN origin routing with no SNI at all. Mitigation path: detect ECH extension (type 0xFE0D) in ClientHello as its own high-signal rule, and force TLS interception for ECH-capable clients.

## 3. ICMP Covert Channel

### (a) Wire artifact
```
IP proto=1, ICMP type=8 code=0
Bytes 0-7: 08 00 <id> <seq> (standard echo header)
Bytes 8+: 0x41 0x42 0x43 ... (encoded payload, non-alphabetic default pattern)
```
Default Windows ping payload is `abcdefghi...` (32 bytes); default Linux is `!"#$%&'()*+,-./`. Any other repeating pattern or size >64 bytes is anomalous.

### (b) Log source / field
- Zeek `conn.log`: `proto=icmp`, `orig_bytes`, `resp_bytes`, `duration`
- Firewall (Palo Alto): `icmp_type`, `icmp_code`, threat log `payload_len`
- EDR process creation: `Image=ping.exe`, `CommandLine`

### (c) Rules

**Suricata** (non-standard payload pattern + size):
```
alert ip $HOME_NET any -> $EXTERNAL_NET any (msg:"ICMP echo with non-standard payload"; itype:8; icode:0; dsize:>64; sid:1000004; rev:1;)
alert ip $HOME_NET any -> $EXTERNAL_NET any (msg:"ICMP tunneling - dnscat2/icmpsh payload marker"; itype:8; content:"|00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00|"; offset:8; depth:16; sid:1000005; rev:1;)
```

**Sigma** (icmpsh/dnscat2 process):
```yaml
title: Suspicious ICMP Tunneling Process
logsource:
    product: windows
    category: process_creation
detection:
    selection:
        CommandLine|contains:
            - 'icmpsh -t'
            - 'ping -s 65500'
            - 'ping6 -s 65500'
    filter_legit:
        CommandLine|contains: '-l 32'
    condition: selection and not filter_legit
level: high
tags: [attack.t1095, attack.t1071.004]
```

### (d) FP analysis / tuning
- **Ops MTU probes / PMTUD** use `ping -f -l 1472` → allowlist `-l 1472` and `-M do`
- **Monitoring agents** (SolarWinds, Nagios) send large ICMP → allowlist source hosts by asset tag
- **dsize:>64** alone is noisy on Linux (64-byte default) → raise to `>96` or require payload-pattern mismatch
- Restrict Suricata rules to `$EXTERNAL_NET` destinations; internal ICMP is mostly legit

### (e) Missed evasion
**Pure timing channel over ICMP.** Operator sends standard 32-byte Windows-pattern pings and encodes data only in inter-packet delay (e.g., 100ms = 0, 300ms = 1). Payload is byte-identical to legitimate ping; `dsize` and content rules see nothing. Reason: the signature matches payload structure, and the signal lives in the timing domain — requires the statistical detection in §5. Also: fragmented ICMP (rare but legal in some stacks) splits the payload marker across fragments, defeating the offset-based content match.

## 4. Cloud-Storage Dead Drop

### (a) Wire artifact
```
PUT /bucket-name/2024-03-15/data.zip HTTP/1.1
Host: s3.amazonaws.com
User-Agent: aws-sdk-java/2.25.x
x-amz-content-sha256: <sha256>
Content-Length: 52428800
```
Key signals: `PUT`/`PutObject`/`UploadPart` burst, new/rare bucket, SDK UA from a host that never used the SDK, multipart uploads (`CreateMultipartUpload` + many `UploadPart`).

### (b) Log source / field
- AWS CloudTrail: `eventName`, `requestParameters.bucketName`, `userAgent`, `sourceIPAddress`, `recipientAccountId`
- Azure Storage diagnostic logs: `OperationName=PutBlob`, `ContainerName`, `CallerIpAddress`
- Proxy: `http_method`, `url`, `user_agent`, `bytes_out`

### (c) Rules

**Sigma** (CloudTrail — new bucket + unusual source):
```yaml
title: Exfiltration to Rare S3 Bucket
logsource:
    service: cloudtrail
    product: aws
detection:
    selection_event:
        eventName:
            - 'PutObject'
            - 'UploadPart'
            - 'PutBucket'
    filter_known_buckets:
        requestParameters.bucketName:
            - 'corp-backup-prod'
            - 'corp-artifacts'
    filter_known_agents:
        userAgent|startswith:
            - 'corporate-backup-agent'
    condition: selection_event and not 1 of filter_*
falsepositives:
    - New application deployment
level: high
tags: [attack.t1567.002]
```

**SPL** (proxy — egress volume to storage ASNs):
```spl
index=proxy url IN("*s3.amazonaws.com*","*.blob.core.windows.net*","*storage.googleapis.com*","drive.google.com*")
| stats sum(bytes_out) as total_out, dc(url) as uniq_paths, count by src_ip, url_domain
| where total_out > 500000000 OR (uniq_paths > 50 AND total_out > 100000000)
| eval total_out_MB = round(total_out/1048576,1)
```

### (d) FP analysis / tuning
- **Backup/CI agents** (Veeam, GitHub Actions artifact upload) → allowlist by `userAgent` AND `src_ip` asset tag; never by bucket name alone (bucket names are guessable)
- **Log-shipping services** to S3 → allowlist destination ARN + IAM role
- Volume threshold `500MB` tuned to P99 of baseline per-host egress; start high, ratchet down
- Key discriminator: **first-seen (bucket, src_ip) pair** — use a lookup-based "rare destination" enrichment rather than static lists

### (e) Missed evasion
**Reusing an existing legitimate bucket/prefix.** Operator drops files into the same bucket the org already uses for backups, with the same SDK UA, from a compromised host that already has S3 permissions. Every field matches baseline; the rare-pair logic fails because the pair isn't rare. Reason: the rule keys on *where* and *who*, not *what* — needs DLP content inspection (file classification on the object) to close. Also: presigned URLs generated by a trusted role shift the anomaly to the signing event, which this pack doesn't cover.

## 5. Covert Timing Channel

### (a) Wire artifact
No payload signature. The signal is:
```
Inter-packet delay: 200ms = "1", 50ms = "0"  (on/off keying)
or: packet size bimodality: 1500B = "1", 60B = "0"
or: TCP retransmission count as the symbol alphabet
```
Wire-visible signature: unusually regular or bimodally-distributed timing/size to a single destination over long duration.

### (b) Log source / field
- Zeek `conn.log`: `duration`, `orig_bytes`, `resp_bytes`, `conn_state`, per-conn timestamps
- NetFlow v9: `FIRST_SWITCHED`/`LAST_SWITCHED`, `IN_BYTES`, `TCP_FLAGS`
- EDR: process network-behavior baselines

### (c) Rule

**SPL** (inter-arrival regularity — low jitter is the tell):
```spl
index=zeek sourcetype=zeek:conn
| bin _span=1h
| stats count as pkts, stdev(orig_ip_bytes) as size_sd,
        avg(duration) as avg_dur, dc(id.resp_h) as dst_count by src_ip, id.resp_h, _span
| where pkts > 500 AND size_sd < 15 AND dst_count == 1
| eval cv = size_sd / avg(orig_ip_bytes)
| where cv < 0.1
```

**Zeek script** (bimodal size distribution):
```zeek
event packet_event(c: connection, p: pkt_hdr) {
    if ( p?$length ) {
        sizes[p$length] += 1;
        if ( |sizes| == 2 && total_pkts > 200 ) {
            # bimodal size distribution to single dst = size-keyed covert channel
            NOTICE([$note=CovertChannel::BimodalSize,
                    $msg=fmt("bimodal sizes %s to %s", sizes, c$id$resp_h),
                    $conn=c]);
        }
    }
}
```

### (d) FP analysis / tuning
- **Keepalive-heavy protocols** (SSH, RDP idle, websockets) → these have *irregular* timing; the rule targets low CV, so exclude `service in ("ssh","rdp")` or raise `pkts > 1000`
- **Streaming media** has regular packet cadence → exclude `id.resp_p in (1935, 554, 8554)` and known CDN ranges
- **NTP/monitoring polls** → allowlist destination ports 123, 6379 for known pollers
- The `cv < 0.1` threshold is the core tuning knob: legit interactive traffic runs 0.3–1.0; covert channels must be regular to be decodable. Raise to 0.15 if FP rate >1/day.

### (e) Missed evasion
**Jitter-mimicking encoding.** An operator who adds noise calibrated to the target's normal traffic CV (e.g., encoding in the *presence/absence* of retransmissions, or in TCP window scale updates) stays above the 0.1 CV threshold while remaining decodable with error-correcting codes. Reason: any statistical threshold is a tradeoff — regularity is needed for decodability, but FEC lets the operator afford 20–30% noise, which lands inside the FP-tuned band. This variant is fundamentally a detection-*engineering* problem (baseline per host-pair, not global thresholds), not a signature problem.
