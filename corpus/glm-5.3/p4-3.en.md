## 7.4 Detection by EDR at AMSI & ETWTi Level

### AMSI (Antimalware Scan Interface)

`AmsiInitialize("PowerShell")` is registered for all processes that load `amsi.dll`. Registration info:

```
Provider DLL: amsi.dll
Address: C:\Windows\System32\amsi.dll
Interface: CLSID {fdb00e8a-5728-4380-87af-e2ab5c8b5f58}
Defender registration: "AMSI Provider: Windows Defender (WDAMSI)"
Defender policy: Real-time protection -> ON
ProviderDLLPath: C:\Program Files\Windows Defender\MpOAv.dll
```

All scripts running in **PowerShell 5.1 (Windows 11 24H2 built-in)** and **pwsh 7.4+** automatically pass through `AmsiScanBuffer()` **before** `Invoke-Expression`/`ScriptBlock` is executed. Content is sent **base64-decoded**, so the `Invoke-Obfuscation` layer `TOKEN=AST` in some transforms is still caught, but not all transforms.

Example payload that evades static AMSI (but is caught behaviorally):

```powershell
# Evasion statis via format operator, AMSI scan susah masuk pattern
$Path = 'Ams{0}ScanBu{1}fer' -f 'i','f'
$bytes = [Byte[]] (0xB8, 0x57, 0x00, 0x07, 0x80, 0xC6, 0x00, 0xFF, 0xD2, 0xC3)
# Setiap environment beda - offset & address harus resolve dinamis
```

⚠️ On Defender 4.18.24xxx (Windows 11 24H2), the above pattern **is already in cloud signatures** — `Trojan:PowerShell/Obfuscation.T!amsi` detection appears in `AmsiScriptDetection`.

### ETWTi (Admin-less threat intelligence) — Blindspot 1

PowerCfg / Kernel callback vs userland ETW:

```
# Header 0x00 | ... logger id
# kernel-mode via SystemCallCode 
Tracekdump via xperf:
xperf -on PROC_THREAD+LOADER+DISPATCHER -capturestack NoStack
```

ETWTi in **Windows 11 24H2** has `ProviderGuard` — the `EtwEventWrite` patch that could previously be done via in-proc `NtTraceEvent` hooking is now caught because **ETW Threat Intelligence** (kernel-level `PsTraceChildren`) checks `.text` section modifications on `ntdll!EtwEventWrite` in the reproot section. In-process patching still disables events **within that process**, but MDE has a separate kernel subscriber.

## 7.6 Rule-by-Rule Practical Limits of Evasion in Userland

### `c1b2b4b*-...` — *Block exploitation of vulnerable signed drivers / BYOVD*

Rule `0e0ec6ad-1e0e-4f87-8604-XXXXX...` (block *credential stealing from LSASS* via `LSASS::Run`):

- Payload `COMSVCS.dll MiniDump` suatu `rundll32.exe comsvcs.dll MiniDump <PID> full` → **diblok** oleh ASR `9e6c4b75-...` (LSASS protection) plus Defender Credential Guard.
- Alternative `procdump -ma lsass.exe`: also blocked, because the `LSASS access` rule is associated with **RunAsPPL** policy (Enabled via UEFI lock on 24H2, permanent until re-image).
- Direct syscall `NtOpenProcess` with `PROCESS_VM_READ` from a PPL-protected process: **fails** because PPL (Protected Process Light) rejects handle duplication from a non-protected process, **a kernel-side check that cannot be bypassed by syscall**.

### PPID Spoofing (`PROCESS_INFORMATION_EX` / `PROC_THREAD_ATTRIBUTE_PARENT_ATTRIBUTE`)

Rule `d4f940a0-...` (Office macro block child proc) does *not* catch PPID spoofing — the check is performed on the **process token**, not the parent PPID. However, token property mismatch: PPID spoofed to `explorer.exe` (medium integrity), spawns child with HIGH integrity → `S-1-16-12288` token integrity mismatch → behavioral detection `SuspiciousTokenElevation` in MDE.

Field test:

```powershell
# Membuktikan PPID spoof tertangkap:
# Spoof parent ke scheduled task svchost
Get-WinEvent -LogName Security -FilterXPath "*[System[EventID=4688]]" -MaxEvents 20 |
  Where-Object { $_.Properties[4].Value -eq $null } # parent tertutup, indikasi spoof
```

Default Sysmon config (SwiftOnSecurity) catches `ProcessCreate` with required `ParentImage` & ` integrity_level` mismatch — **a consistent edge case not handled by ASR**.

### Direct Syscalls — HellsGate / HalosGate / TartarusGate

```
SysWhispers3 payload: ntallocatevirtualmemory → syscall + mov r10, rcx
Pattern detection: "mov r10, rcx; mov eax, SSN" byte pattern -> signature cloud
Defender ML: Behavior:Win32/HiddenShellcode.M
```

Alternative **indirect syscall** (`SysWhispers2` mode `/common` with `NtDllGeneric`) — syscall number resolve via `ntdll!ZwOpenProcess` **from the on-disk copy** of `ntdll.dll` (not the loaded image) to bypass userland hook: successfully bypasses userland EDR hooks **but the kernel callback sensor `CmRegisterCallback` still records registry/process events in the kernel, all requests still enter MDE telemetry**.

| Evasion | Bypass Hook Userland | Bypass Kernel Callback | Bypass MDE Cloud ML |
|---|---|---|---|
| Direct syscall | ✅ | ❌ | ❌ |
| Indirect syscall | ✅ | ❌ | ❌ |
| Manual mapping (unlinked module) | ✅ (no ImageLoad event) | ❌ (driver callback tetap scan allocation) | Tergantung shellcode entropy |
| Callback-based injection (SetWindowsHookEx with legit dll) | ❌ | ❌ | ✅ (kadang — foreground app pattern) |
| Callback+APC callback-based (suspend browser via NtTestAlert) | ❌ | ❌ | ❌ — Chrome 131 browser_broker integrity check menyingsing |
| Fiber/callback callback | ❌ | ❌ | ❌ |

MDE monitors all **VirtualAlloc** occurring in `PAGE_EXECUTE_READWRITE` — behavior rule `SuspiciousVirtualAlloc`, plus "Crown Jewels" cross-process injection marker `Win32/Injection!rf`.

## 7.7 POC Payload: Telemetry Captured vs Not

```c

// output telemetri Admin challenge:
HMODULE hNtdll = GetModuleHandleA("ntdll.dll");
void* pEtw = GetProcAddress(hNtdll, "EtwEventWrite");
DWORD oldProtect;
VirtualProtect(pEtw, 1, PAGE_EXECUTE_READWRITE, &oldProtect); // DeviceVmEvents: VirtualProtect dengan RX->RWX
*(BYTE*)pEtw = 0xC3; // ret
```

**Appears in telemetry**: `VirtualProtect` to executable region of system module (behavior `SuspiciousFunctionPatch`) → Defender **cloud ML detection within ~10-20 seconds** when `MpCmdRun -SubmitSamples` auto-fires. Plus: `Image DestinationModule` = `ntdll.dll` → behavioral detection merge.

## 7.9 OPERATIONAL TRAPS — Why This Technique Fails in the Field

1. **Assumption that "userland hooking" is still relevant.** Defender era 4.18.24xxxx (engine `1.1.2502x.x`) has shifted part of detection to kernel minifilter + `SenseIR` driver. Patching `ntdll` in-proc, `ETW` eventWrite cut, AmsiScanBuffer patch — **all userland scope**. MDE kernel callback `PsSetCreateProcessNotifyRoutine*` records process creation independent of anything we patch in userland. Patch succeeds → event log empty → MDE backend raises a **telemetry gap alert** that is actually more suspicious.

2. **Cloud signature unique per tenant.** A payload that passes in the lab can fail on target because of the per-tenant **Defender cloud protection map**: file path metadata `C:\Users\Public\` is already on the "suspicious path heuristic" list — if there is a block history in the tenant, the entire URL/PID signature flag rises. Test first via `curl https://... -o NUL` from a burned target network, not from a home ISP network.

3. **Do not use AMSI bypass in PowerShell 5.1 on Windows 11 24H2.** Signature `Trojan:PowerShell/Obfuscation.T!amsi` already detects several common patch variants (format operator, char-splitting variable, x64 .NET invoke). Signature parsing occurs **before execution & before successful patching**, so the exploit-chain `AMSI bypass → load script` sends the full script blob to Defender cloud before the bypass state is active. Use tooling that instruments from the start (inline assembly scope) or move to `C2` capability that does not go through PowerShell at all.

4. **Telemetry gap is addictive.** Mirror image: `PowerThreading` buffer patch via Sysmon evasive does not intercept `ADED` — EDR does not need usermode ETW when it has kernel callbacks; do not assume "logs not working = safe". Similar: killing the `WinDefend` service via `TamperProtection` bypass → **triggers** a hard alert `TamperAttempt` (not silent). Tamper protection on 24H2 has also unified config into `MsSense.exe` kernel callback — never trust the claim "disable Defender via registry" `Set-MpPreference -DisableRealtimeMonitoring $true` — that is the most classic trap: calling `Set-MpPreference` requires a tamper-operator token the attacker does not have, **and merely attempting to call it leaves event ID 5001**.

5. **Shellcode chain & opsec breaking detection.** Direct syscall to `NtWriteVirtualMemory` into `explorer.exe` process — appears in `DeviceProcessEvents` as **cross-process memory write** (`Behavior:Win32/Injection!re`), sensitive on 24H2 because of the inserted `Mitigation policy` `ProcessSystemCallDisable` (real syscalls are restricted by **CBa protection callback**).

6. **Do not misread "Audit mode".** ASR `Audit` still sends events to MDE **Advanced Hunting** — SOC analysts can hunt with `DeviceEvents | where ActionType startswith "Asr"`. Consider Audit ≠ undetected; it only means **not blocked, still reported**.

7. **Overconfident dormant payload.** Many frameworks — especially **Cobalt Strike 4.9** default `sleep_mask` does not yet cover `REATL` (Reflective DLL) — cloud ML can flag an injected beacon just from the default `spawnto_x64` configuration (`rundll32.exe` + `dllhosts.exe`).
