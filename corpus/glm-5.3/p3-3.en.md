# Reference Chapter: Scanning Attachment Evasion

## 1. Overview of the Scanning Pipeline

Typical email gateway stack faced by red team:

| Component | Product/example | Behavior |
|---|---|---|
| MTA | Postfix 3.8, Exchange 2019 transport | Size limits, header filter |
| Scanner antivirus | ClamAV 1.3, Windows Defender 1.4x (platform KB | Signature-based, archive depth limit |
| Sandbox detonasi | FireEye, Any.Run, Cuckoo | Deteksi detonasi makro/binary, timeout 120-180 detik |
| Content filtering | native MS Exchange rules, Proofpoint, Mimecast | Blocking ext, password-protected archive policy |
| ATP email | Microsoft Defender for Office365 Safe Attachments | Analisa dinamis, timeout hard ~3 menit |

Basic evasion principle: **the scanner has a limited time budget and recursion depth**. Any payload that makes scan resources exceed the budget will let the object through (fail-open in the majority of default deployments).

## 2. Technique: Archive Nesting (Layered Wrapping)

### 2.1 Bom Kompresi Klasik

**What is sent:** ZIP containing an RLE/highly-repetitive file that expands ~1000x.

```bash
# Buat 1 MB yang expand jadi ~10 GB (ratio ~10000:1)
python3 - <<'EOF'
import zipfile, zlib
with zipfile.ZipFile('bomb.zip', 'w', zipfile.ZIP_DEFLATED) as z:
    z.writestr('payload.txt', b'\x41' * 10_000_000_000 // 10000 * 1)
EOF
```

Or nest:

```bash
zip -9 a.txt.zip a.txt        # level 1
zip -9 a.zip.zip a.txt.zip    # level 2
... # hingga 10-20 lapis
zip -9 final.zip a.zip.zip ... # kirim ini
```

**What appears gateway-side:**
- ClamAV default: `MaxRecursion 16`, `MaxFiles 10000`, `MaxScanSize 400M`, stream size `StreamMaxLength 100M` — error `[LibClamAV]::Limits exceeded` → **verdict OK (skip)** in many fail-open configurations.
- Microsoft Exchange 2019 transport default `ExtractedZipFileCountLimit` = 1000, `ExtractedFileSizeLimit` = 1GB.
- SMTP level: the `nested_zip` operand has been available in Exchange transport rules since 2016.

**Why it works:** the scanner runs out of time before touching the original payload in the deepest layer. The classic 42.zip (42 layers, 4.3 PB expanded) still references default budget limits in many products.

**Why it fails:** mature deployments set fail-closed — ClamAV `AlertExceedsMax` yes, sends verdict `Infected.Bom`/`Heuristics.Limits.Exceeded`. Modern gateways (Defender for Office 365) flag `DepthBomb` and quarantine.

### 2.2 Nesting Format Campuran

Different overload engines have different parsing per format. Chains proven to increase scan time:

```
.zip → .7z (password) → .tar.gz → .iso → payload.exe
```

Or use formats whose extensions are rarely firewalled:

```bash
mv payload.bin 'archive.uue'         # uuencoded
tar czf arc.tar.gz payload.lzh       # LHarc jarang di-blocklist ext
# ext yang umum lolos filter ext: .lzh .cab .arj .ace .iso .vhd .vhdx .img .swm .wim .vhd
```

**Why it works:** gateway extension filters usually block a small enumeration (*.zip, *.rar, *.7z, *.exe) and do not cover disk image/multi-part containers. The following activity log and ClamAV output show gradual truncation:

```
LibClamAV Warning: cli_scanrar: RAR headers exceeding maximum
LibClamAV Warning: Reached max scan size
```
→ verdict clean, mail delivered.

## 6. Operational Pitfalls That Make the Technique Fail

1. **PT file quotas** — force `zip -s 10m` split, SMTP multipart blocked by internal `Send-Connector` max message size 35MB by default (Exchange). 7z split files are not readable by bank-side numeric-version tweakless tooling; red team must verify single-part delivery with `recv` checksum.
2. **Fail-open is not uniform** — ClamAV front-end case-by-case; gateway second-stage (Defender O365 dynamic) can quarantine *after* thử delivery to the target mailbox, timing your payload click rate matters (user clicked before detonation-complete = win; auto-keyed callback post-quarantine blew beacon cover).
3. **Password-archive policy** — perusahaan sektor finansial men-set all-password-zip alert (chall "Invoice_kwrjhp4.zip" beacon cover identity split forced).
4. **Sentinel agent check-in / file restart + rescan** — OneDrive sync runs attach on download → CD file combinatorial hash MDATP-trigger rescan queued object that was initially proven safe; post-sync verdict `VeryHigh confidence malware` retrigger major event *after C2 ternya* — injection still possible but risk staging without walet cover.
5. **MTA rewrite magic headers** — sendmail/Postfix prepend Content-Type `multipart/mixed` boundaries, mem modifies original MIME; hard-error → generate double-copy, corrupted analysis or polyglot region offset shift, `CRC mismatch` signature.
6. **Recipient preview client behavior** — signing key `S/Mime` wrap subject metadata effort mail-hosten trigger-or re-analysed audit qualitative report number of handoff chainraisers — campaign OPSEC burn.
7. **Fail-closed hard-switch commoner** — modern default egress mode `quarantine on limits` changes the legacy compression bomb paradigm from "evasion jackpot" to "self-report trap". Test with a benign bomb canary first in your own environment before committing the technique to the plan.
